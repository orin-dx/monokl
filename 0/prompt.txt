## 1. ML-based type/fact inference — confidence signal & calibration

- **DeepTyper** (Hellendoorn, Bird, Barr, Allamanis, "Deep Learning Type Inference," ESEC/FSE 2018, DOI 10.1145/3236024.3236051) — REAL, verified via full-text PDF. Confidence = raw softmax probability of the top RNN prediction (Eq. 1 in paper: `P(τ) = softmax(...)`). Used directly as a precision/recall threshold: paper's own numbers show a 90% confidence threshold yields only ~80% precision, and a 99% threshold yields ~95% precision (Fig. 5). That gap (0.90 stated confidence → 0.80 actual correctness) is a textbook calibration gap — but the paper never uses the word "calibration" and does no reliability-diagram/ECE/Brier analysis. It's an unexamined side effect visible only in their raw results table.
- **TypeWriter** (Pradel, Gousios, Liu, Chandra, arXiv 1912.03768 / ESEC-FSE 2020) — REAL. Notably does NOT lean on model confidence at all — it validates predictions by round-tripping candidate types through a real gradual type checker and search, i.e. confidence is established by an independent symbolic oracle, not trusted from the model.
- **Type4Py** (Mir, Latoskinas, Proksch, Gousios, ICSE 2022) — REAL. Uses nearest-neighbor similarity ranking (MRR), not a calibrated probability at all.
- **HiTyper** (Peng, Gao, Li, Gao, Lo, Zhang, Lyu, ICSE 2022) — REAL. Hybrid: static "type rejection rules" filter/veto neural predictions rather than trusting a confidence score.
- **OptTyper** (Vlassi Pandi, Barr, Gordon, Sutton, arXiv 2004.00348) — REAL (note: 4th author is Charles Sutton, not Lahiri). Combines hard logical constraints from a real type system with a learned "natural" signal via continuous optimization — again, a symbolic check gates the statistical one.

**Pattern across all five:** none does formal calibration analysis, and every single one that ships a real system pairs the statistical signal with an independent symbolic validator rather than trusting raw model confidence. That validator-gates-model pattern is structurally identical to what monokl's sentinel/categorical design already does.

## 2. Naturalness of software (lightweight, non-ML)

**Hindle, Barr, Gabel, Su, Devanbu, "On the Naturalness of Software," ICSE 2012 (CACM 59(5) reprint 2016, DOI 10.1145/2902362)** — REAL, verified via full-text. Core method: plain n-gram MLE frequency counting over a code corpus (no neural net, no training pipeline — literally token co-occurrence counting), scored via cross-entropy/perplexity. This is genuinely lightweight — could run over monokl's own indexed corpus. Lineage confirmed: **Ray, Hellendoorn, Godhane, Tu, Bacchelli, Devanbu, "On the 'Naturalness' of Buggy Code," ICSE 2016** (DBLP-verified) empirically shows buggy lines score measurably less "natural" (higher entropy) than clean code — a real, direct precedent for using a statistical anomaly score as a confidence-adjacent signal, entirely apart from any ML type-inference model.

## 3. Ensemble/multi-tool agreement

**Habib & Pradel, "How Many of All Bugs Do We Find? A Study of Static Bug Detectors," ASE 2018** (DBLP-verified, DOI 10.1145/3238147.3238213) and **Lenarduzzi, Pecorelli, Saarimäki, Lujan, Palomba, "A Critical Comparison on Six Static Analysis Tools," JSS 2023** (DBLP-verified) — both REAL. Both found LOW agreement/overlap between independent static analyzers on real code — tools mostly find disjoint issue sets. This actually argues against naive "multi-tool agreement = confidence" reasoning: absence of agreement is the norm even among sound analyzers, so agreement can't be treated as a reliable confidence multiplier without a lot more calibration work of its own.

## 4. Bayesian/lightweight combination specifically for program analysis

Did NOT find real Dempster-Shafer work specifically applied to program analysis/verification — the DS papers I found were generic (not program-analysis-specific), so don't claim that citation. What IS real and directly on point:
- **Kremenek & Engler, "Z-Ranking: Using Statistical Analysis to Counter the Impact of Static Analysis Approximations," SAS 2003** — REAL. Simple frequency/z-score statistical model ranking static-analysis error reports by true-positive likelihood, no ML training required.
- **Kremenek, Ashcraft, Yang, Engler, "Correlation Exploitation in Error Ranking," FSE 2004** (DOI 10.1145/1029894.1029909) — REAL. Uses Bayesian factor graphs + belief propagation to combine multiple correlated static-analysis signals into one ranking/confidence value. This is the best real precedent for "combine several independent uncertain signals into one number, for program analysis specifically" — and it's 20+ years old, lightweight, no deep learning.

## 5. Honest verdict for monokl

The literature does not push toward a neural/ML confidence score — quite the opposite. Every real ML type-inference system either lacks calibration analysis or (when scrutinized, as with DeepTyper's own numbers) shows raw confidence overstating true accuracy, and every shipped system ends up gating the statistical signal with an independent symbolic check anyway — which is what monokl's categorical + sentinel design already is. Multi-tool agreement is empirically rare even among correct analyzers, so it's a weak standalone signal. The one genuinely defensible "beyond categorical" move, if you want one, is the Kremenek/Engler-style lightweight statistical combination: take signals monokl already computes per-span (PrecisionAnnotation tier, sentinel-denylist hit, optionally a cheap n-gram/naturalness anomaly score from its own corpus) and combine them with simple classical statistics (a z-score-style ranking or a small Bayesian/log-odds combinator) into a single ordering — not a trained/calibrated absolute probability. That requires no training pipeline, no ML infra, and has direct 20-year precedent in program-analysis literature specifically (not borrowed from an unrelated ML domain). Recommendation: keep `CapabilityPrecision`'s categorical tiers as the ground truth users see; if you want finer ranking for internal use (e.g. sorting query results by trustworthiness), add a Z-Ranking-style combinator over existing signals rather than a numeric confidence score presented to users as a probability — presenting an uncalibrated number as if it were a calibrated probability would be actively misleading given what the ML literature itself shows about calibration gaps.
