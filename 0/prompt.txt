## 1. MonkeyType — verified against Instagram/MonkeyType source, not memory

Mechanism: uses `sys.setprofile` (a profiling hook, not `sys.settrace`) to interpose on function calls, returns, and generator yields during real test execution, recording the concrete types observed (github.com/Instagram/MonkeyType README).

Multi-type handling: in `monkeytype/stubs.py`, `shrink_traced_types()` collects every observed type per argument/return/yield across *all* traces into a set, then calls `shrink_types()` to reduce that set to a minimal-equivalent type — effectively a full union (e.g. collapsing to `Optional[X]` when `None` appears), not a "most common type" heuristic.

Confidence: none, explicitly. There is no frequency count, no "seen 95% of calls" score. The docs state annotations are "an informative first draft, to be checked and corrected by a developer" — the confidence mechanism is human review, not an automated score. This is real precedent for confirming a static guess with a *fundamentally different* signal source (execution rather than parsing), but it stops at "recording observed reality," it does not model confidence.

## 2. JS/TS equivalent

**TypeWiz** (github.com/urish/typewiz) is real and did exactly this — runtime monitoring during execution auto-annotates TS with observed types. But it's dead: last release Apr 2019, repo explicitly archived Oct 2021 with an owner note "as of 2021 I'm no longer working on TypeWiz." No actively maintained equivalent found. Treat as historical precedent only, not a tool to integrate with or model implementation details on.

## 5. Recommendation

Don't reach for Dempster-Shafer or Bayesian combination — both require inputs monokl doesn't have (mass assignments over a frame of discernment, or calibrated priors/likelihoods from training data). Given only categorical tier, candidate-set size, sentinel-degradation, and cross-tier agreement, the defensible approach is a small **deterministic ordinal downgrade lattice**, not a numeric probability:

- Start from the categorical tier as the baseline (already the primary signal).
- Each secondary signal can only *downgrade* confidence one step, never algorithmically upgrade it — this avoids manufacturing false precision from what are really just fewer red flags, not more positive evidence. `candidate_set_size > 1` → downgrade one level (ambiguous); sentinel-degradation detected → downgrade one level.
- The one signal allowed to counteract a downgrade is genuine cross-tier agreement (two independently-derived analyzers concurring) — that's authentic corroboration from a different source, structurally the same kind of "confirm with a different signal" precedent MonkeyType embodies, just applied deterministically instead of via observed-frequency.
- Implement as a small enum + explicit combination function (~50-100 lines, unit-testable), explainable directly in `michi`-formatted output (e.g. "high, downgraded: ambiguous candidate set"). No library needed for any part of this.
