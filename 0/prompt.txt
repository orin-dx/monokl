2. Key Technical Concepts:
   - Two-level architecture: `LanguageAnalyzer` (per-file, produces owned `FileAnalysis`) + `WorkspaceEnricher` (folds per-file analyses into `WorkspaceIndex`, containing `ImportGraph` + `SymbolIndex`).
   - Arena lifetime containment (ADR 0002): no OXC `Allocator`-borrowed data may escape a per-file `analyze()` call; everything in `FileAnalysis` must be owned.
   - `CapabilityPrecision` model: `Unsupported < Heuristic < Structural < Exact` — lets different language analyzers report different resolution quality per operation, with `Skipped`/`Warning` diagnostics instead of silent failure/crash.
   - `AnalyzerRegistry` — dispatches files to the first matching `LanguageAnalyzer`; composite `config_hash` for cache invalidation.
   - Two-tier cache: mtime/size fast-path → blake3 `ContentHash` fallback; two storage layers (in-memory `DashMap`, disk-persisted `.monokl/cache.json` version+config-hash gated).
   - 8-stage `search` pipeline: query parse → canonicalize → text prefilter (`grep-searcher`) → boolean eval → block retrieval → BM25 rank (K1=1.5, B=0.5) + node-type/coverage boosts → dedup (>50% line overlap) → token budget (tiktoken o200k_base, 2MB hard cap).
   - `TraitImplEnricher`/`TraitImplIndex` — new design (added to spec) for a reverse "who implements this trait" index, modeled on rust-analyzer's `trait_impls_in_crate_query` and rustdoc's implementors-list generation; composes with `SymbolIndex`/`ImportGraph` via a hardened, capped BFS (enqueue-time `FxHashSet` visited-set, explicit depth limit, cap checked at every push site, `TraversalCapExceeded`/`TraversalReport` instead of silent truncation).
   - `cache_tiers::lookup_or_parse` — newly extracted shared helper (parameterized over `from_persisted`/`cached_is_valid`/`parse` closures) unifying `TsAnalyzer`/`RustAnalyzer`'s previously-duplicated 4-tier cache skeleton.
   - `MonoklError` (thiserror-based, `#[non_exhaustive]`) — variants: `Io`, `Walk`, `RegexBuild`, `NonUtf8Path`, `TooManyTerms`, `TokenizerInit`, `Json`, `PathOutsideRoot`, `StaleDiskCache`, `InvalidGitRef`, `Git`, `SymlinkRejected`, `FileTooLarge`, `LockPoisoned` (all now correctly declared after fixes; `Parse`/`Query` removed as dead code).
   - `LanguageAnalyzer` trait (now complete): `language_id() -> LanguageId`, `supports()`, `capabilities() -> AnalyzerCapabilities`, `analyze_with_profile()`, with `analyze()` as a default method delegating to `analyze_with_profile(..., AnalysisProfile::Full)`.
   - `LanguageId` enum: `TypeScript, Rust, Python, Go, Java` (no CSharp — dropped per roadmap decision).
   - `LangData` enum (`#[non_exhaustive]`, serde tag="language"/content="data"): `Ts, Rust, Python, Go, Java` (CSharp variant removed/replaced).
   - `AnalysisProfile` enum: `Dependencies, Structural, Full`.
   - BM25 tuning (K1=1.5, B=0.5), rounding to 6 decimals for cross-platform determinism.
   - Non-goals (documented in PRINCIPLES.md): no persistent search index, no full Salsa (yet — open track), no embedding-based retrieval by default, no stemming, no in-memory trigram index (rejected: measured 600MB-1.2GB), no tree-sitter for TS/JS (OXC instead), no running agent loop.
   - Native parser landscape per language: TS/JS = OXC (native Rust, adopted); Rust = `ra_ap_syntax` (kept over `syn` — syn's fail-fast parsing is a real regression for scanning WIP/broken code); Python = tree-sitter-python (Ruff's Rust-native crates rejected as unstable); Go = `gosyn` (real, viable native Rust parser — the standout finding); Java = tree-sitter-java (no viable native Rust parser exists).
   - `oxc_semantic` — recommended addition for TS/JS scope-aware reference resolution (lockstep-versioned, same arena discipline as existing OXC deps).
   - `ra_ap_hir` / Salsa — real Rust semantic resolution capability, but daemon-only cost model; Salsa flagged as an independent, lighter investigation track (real precedent: Astral's `ty`/red-knot, Biome) decoupled from the `ra_ap_hir`-needs-a-daemon question.
   - SCIP (Sourcegraph Code Intelligence Protocol) — currently under active research (background agent still running) for potential relevance to monokl's symbol identity/relationship modeling and possible output-format or ingestion strategy.
   - Eval harness design (recommended, not yet built): two-layer — deterministic retrieval eval (RepoBench-R/CodeSearchNet-style recall@k/MRR) + agent A/B (model/effort pinned, ≥5 runs/condition median+IQR, ≥10 repos frozen task list, report token AND dollar cost separately, broken out by cache-read vs fresh-input mix).
   - Rust workspace clippy lint policy: deny `unwrap_used`, `expect_used`, `panic`, `unreachable`, `unimplemented`, `dbg_macro`, `todo` in lib code (allowed only in `#[cfg(test)]`); `unsafe_code = "deny"`.
   - `camino::Utf8Path`/`Utf8PathBuf` used everywhere instead of `std::path::Path`; `rustc-hash::FxHashMap`/`FxHashSet` for hot-path maps; `BTreeMap` for anything serialized to JSON (deterministic key order).
   - RTK (Rust Token Killer) — user's global bash-command proxy (per their global CLAUDE.md) that summarizes/truncates verbose bash output for token savings; occasionally produces misleading summarized output (e.g. "[N more lines]" instead of real `head` output) requiring the Read tool for precision instead.
