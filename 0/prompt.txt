## Concrete patterns worth carrying into Monokl

- **Depend on `michi` directly** for TOON list rendering / errors / hints rather than reinventing — it's designed exactly for this (`toon::list(...).total(n).hint(...).render()`).
- **Errors**: `thiserror` (2.x), a single `michi::Error` enum with agent-renderable output + retry classification (`src/error.rs`).
- **Lint/quality bar** (`.clippy.toml`, `deny.toml`, `CLAUDE.md`): no `unwrap`/`expect` in lib code, `#![deny(unsafe_code)]` scoped-allow only at FFI boundary, `disallowed-macros` banning `println!`/`eprintln!`/`dbg!` in lib code, cognitive-complexity threshold 20, `cargo-deny` license allowlist with explicit AGPL exception for the crate itself.
- **Workspace layout**: root crate is pure/sync with zero default deps; a thin second crate (`packages/michi-node`) exists solely for `crate-type = ["cdylib"]` NAPI export, re-exporting via `pub use crate::napi::*` — real logic stays in the main crate's `src/napi.rs`, gated `#[cfg(feature = "napi")]`.
- **Feature-gating pattern**: pure/sync core always compiled; async/heavier extensions (tokio-based `pipeline`, `cache` via `moka`+`sha2`, `fuzzy` via `nucleo-matcher`, `cli` via `indicatif`/`inquire`/`crossterm`) live in the same module directory but behind opt-in features, documented via a dependency mermaid graph in `ARCHITECTURE.md`.
- **Testing**: `cargo nextest`, `insta` snapshots (`tests/snapshots/*.snap`), `proptest`, `divan` for benchmarks (not criterion).
- **Docs style**: numbered `docs/00-overview.md`, `docs/01-spec.md` (verbatim-checked code examples), plus a `docs/superpowers/specs/` and `docs/superpowers/plans/` directory for long-form design/implementation-plan documents (e.g. `docs/superpowers/specs/2026-07-03-michi-design.md`, `docs/superpowers/plans/2026-07-03-michi-core.md`) — this is the "reconstruction-grade spec" authoring pattern you're looking for.
