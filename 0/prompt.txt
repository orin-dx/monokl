     - `Option<T>` fields get implicit missing-key/null deserialize leniency from serde's derive macro regardless of `#[serde(default)]`; `Vec<T>` fields do NOT get this — `#[serde(default)]` is load-bearing for `Vec<T>`, redundant for `Option<T>`.
     - Variant-level `#[serde(rename_all = "camelCase")]` on an enum lowercases only the leading character of an already-PascalCase variant name (does not restructure internal word boundaries); field-level `rename_all = "camelCase"` on a struct DOES restructure across underscores (`trait_impl` → `traitImpl`).
     - Enum-level `rename_all` renames only the variant TAG, never the fields of struct-shaped variants — that needs the separate `rename_all_fields` attribute, which was absent everywhere checked, so struct-variant field names stay in Rust snake_case on the wire regardless of the container attribute (this was gotten WRONG on the first attempt in SPEC-005's AC-005, a serious, high-stakes error, fixed after empirical toolchain reproduction).
     - `#[non_exhaustive]` is purely a Rust-compiler exhaustive-match attribute; it has zero effect on serde's generated (de)serialize code.
     - `#[serde(deny_unknown_fields)]`'s absence means unrecognized JSON keys are silently discarded, not rejected — true for plain structs AND for internally-tagged/adjacently-tagged enums alike.
     - Internally-tagged (`tag = "kind"`, no `content`) vs. adjacently-tagged (`tag = "language", content = "data"`) serde enum representations produce structurally different JSON shapes (fields flattened alongside the tag vs. tag+payload in separate keys).
     - `#[serde(flatten)]` on a struct field merges that field's own JSON keys directly into the parent object with no nesting — newly relevant for SPEC-006's `RankedBlock { #[serde(flatten)] block: CodeBlock, ... }`.
